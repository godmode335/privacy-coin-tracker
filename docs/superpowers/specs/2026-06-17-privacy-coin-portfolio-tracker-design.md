# Privacy-Coin Portfolio Tracker — Дизайн (спека)

**Дата:** 2026-06-17
**Статус:** утверждён к реализации (MVP)

## 1. Резюме

Нативное Windows-приложение (desktop) — **портфолио-трекер для приватных
криптовалют**. Все данные пользователя хранятся **локально**; наружу уходят
только публичные запросы цен. Фокус строго на privacy-монетах. Первая версия —
desktop; веб-сайт планируется второй поверхностью с переиспользованием
интерфейса.

## 2. Ключевые решения

| Решение | Выбор |
|---|---|
| Модель учёта | Ручной ввод холдингов + цены через API (CoinGecko) |
| Поверхность (MVP) | Desktop-приложение Windows, данные локально |
| Охват монет | Только privacy-монеты (курируемый список) |
| Стек | Tauri (Rust core + веб-интерфейс + локальная SQLite) |
| Хранение холдингов | На основе сделок (transactions) — точный P&L |
| Доп. функции MVP | Цена покупки и P&L, графики, несколько портфелей |
| Вне MVP | Ценовые алерты, сайт, наблюдение за t-адресами/viewing key |

## 3. Контекст ресёрча (почему так)

- **Zcash** — приватная монета №1 по капитализации (2026), приватность
  опциональная (zk-SNARK). **Monero** — приватность по умолчанию, делистнут с
  многих бирж. Прочие: Dash, Firo, Zano.
- **Доступность данных:**
  - Цены всех privacy-монет — бесплатный API CoinGecko. ✅
  - Zcash прозрачные t-адреса — читаются on-chain. ⚠️ опционально.
  - Zcash shielded z-адреса — баланс **публично не читается** (только с viewing
    key). ⚠️
  - Monero — баланс только через private view key, причём траты не видны →
    баланс ненадёжен. ⚠️
- **Вывод:** надёжная база трекера приватных монет — ручной учёт + цены по API.
  Автоматическое чтение адресов/ключей — опциональная фича *поверх*, не
  фундамент. Перенесено за рамки MVP.

## 4. Архитектура

```
Frontend (веб: HTML/JS/CSS)  ← later переиспользуется для сайта
  • Дашборд портфеля   • Графики
  • Формы ввода сделок • Переключатель портфелей
        │ Tauri IPC (команды)
Rust core
  • db        — слой SQLite
  • coins     — курируемый список privacy-монет + маппинг CoinGecko
  • prices    — клиент CoinGecko (текущие/исторические цены, кэш, бэкофф)
  • portfolio — калькулятор стоимости / P&L / аллокации
  • scheduler — периодическое обновление цен + снимок стоимости
        │
  SQLite (локально, AppData)      CoinGecko API (только цены, исходящий)
```

**Принципы:**
- Всё локально; в сеть уходят только публичные ID монет для запроса цен —
  никаких данных о холдингах.
- Интерфейс общается с ядром через узкий набор команд и не знает про SQLite/API.
  Это позволит later подставить веб-бэкенд для сайта без переписывания фронта.
- `prices`, `db`, `portfolio` — независимые, тестируемые по отдельности модули.

## 5. Модель данных (SQLite)

```
portfolios      (id, name, created_at)
transactions    (id, portfolio_id, coin_id, type[buy|sell], quantity,
                 price_usd, fee, ts, note)
coins           (id, symbol, name, is_privacy, coingecko_id)
price_cache     (coin_id, price_usd, price_btc, updated_at)
value_snapshots (id, portfolio_id, total_usd, ts)
```

- Холдинг = производная от списка сделок (количество и средняя цена входа
  считаются из transactions).
- Денежные суммы хранятся/считаются как Decimal (без float-погрешностей).
- `value_snapshots` копит историю стоимости портфеля локально (бесплатный
  CoinGecko ограничивает историю; стоимость всего портфеля собираем снимками).

## 6. Команды интерфейс → ядро

`list_portfolios`, `create_portfolio`, `add_transaction`,
`list_transactions`, `get_dashboard`, `get_coin_history`, `refresh_prices`.

## 7. Поток данных

- **Старт:** загрузка портфелей из SQLite → показ дашборда из кэша → фоновое
  `refresh_prices`.
- **Обновление цен:** один batch-запрос CoinGecko по всем монетам → запись в
  `price_cache` → пересчёт стоимости/P&L → запись `value_snapshots` →
  обновление UI.
- **P&L:** нереализованный = (тек.цена − средняя цена входа) × количество;
  реализованный — по продажам методом средней цены. Аллокация = доля монеты в
  общей стоимости.
- **Графики:** цена монеты — из CoinGecko history; стоимость портфеля — из
  `value_snapshots`.

## 8. Ошибки и устойчивость

- **Офлайн / rate-limit:** показываем последние цены из кэша с пометкой времени;
  приложение не падает. Экспоненциальный бэкофф (бесплатный CoinGecko ~30 req/min).
- **Целостность:** запись сделок в транзакции БД; деньги — Decimal.

## 9. Тестирование

- Калькулятор P&L и аллокации — модульные тесты (TDD).
- Клиент цен — с замоканными ответами API.
- Слой БД — на временной SQLite.
- Подход — test-driven-development.

## 10. За рамками MVP (будущее)

- Веб-сайт (переиспользование фронта поверх веб-бэкенда вместо Rust-команд).
- Ценовые алерты (Windows-уведомления).
- Наблюдение за t-адресами Zcash и Monero viewing key (с явными оговорками о
  надёжности).
- Налоговый экспорт (модель сделок уже это поддерживает).
